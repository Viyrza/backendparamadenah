# PARAMADENAH - AI Project Context & Coding Rules

## Project Overview

**PARAMADENAH** adalah aplikasi peta kampus Universitas Paramadina yang dirancang untuk membantu mahasiswa dan pengunjung menemukan lokasi gedung, ruangan, dan fasilitas kampus secara intuitif.

### Tujuan Aplikasi
- Menyediakan navigasi kampus yang mudah digunakan
- Menampilkan informasi gedung dan fasilitas
- Memfasilitasi navigasi dari lokasi awal ke lokasi tujuan (gedung)

---

## Technology Stack

### Frontend Mobile
- **Framework**: Flutter
- **Purpose**: Aplikasi mobile untuk menampilkan peta dan navigasi kampus

### Backend Admin
- **Framework**: Next.js (App Router)
- **Language**: TypeScript
- **Purpose**: Dashboard admin untuk mengelola data gedung, fasilitas, kelas, dan users

### Database
- **Primary**: Firebase Realtime Database
- **Purpose**: Menyimpan data gedung, fasilitas, notifikasi, dan user

### Storage
- **Provider**: Cloudinary
- **Purpose**: Menyimpan dan mengelola gambar (bank image)

## Navigation System

### Konsep Dasar
Navigasi kampus **TIDAK menggunakan GPS real-time** sebagai sumber utama. Sebaliknya, menggunakan:

1. **Lokasi Awal**: Dipilih manual oleh user (contoh: Parkiran, Gerbang Utama)
2. **Lokasi Tujuan**: Pilihan gedung dari daftar yang tersedia
3. **Koordinat**: Latitude dan longitude untuk kalkulasi rute

### Contoh Skenario Navigasi
```
User di: Parkiran (navigation_node)
User mau ke: Gedung A
Sistem akan:
1. Ambil koordinat lokasi awal dari navigation_nodes
2. Ambil koordinat tujuan (Gedung A) dari collection gedung
3. Hitung rute menggunakan Dijkstra
4. Tampilkan di Flutter
```

### Data Flow Navigasi
```
Flutter App
    ↓ (request rute)
Backend Admin (Next.js)
    ↓ (kalkulasi Dijkstra)
Firebase (ambil koordinat)
    ↓ (return rute)
Flutter App (tampilkan di peta)
```

## Coding Rules & Best Practices

### 1. Firebase Structure
- ❌ **JANGAN** mengubah struktur Firebase tanpa persetujuan project lead
- ✓ Dokumentasikan setiap perubahan schema di `docs/FIREBASE_SCHEMA.md`
- ✓ Gunakan migration script jika perlu mengubah struktur

### 2. Koordinat & Lokasi
- ✓ **Simpan koordinat di level GEDUNG** (bukan di level kelas)
- ✓ Gunakan latitude dan longitude dengan presisi minimal 4 desimal
- ❌ **JANGAN** menyimpan koordinat di level kelas/fasilitas ruangan
- ✓ Dokumentasikan sumber koordinat (GPS, manual survey, maps API, dll)

### 3. Code Quality
- ✓ Gunakan **TypeScript** untuk semua kode (strict mode)
- ✓ Ikuti Next.js App Router conventions
- ✓ Hindari `any` type - gunakan proper typing
- ✓ Pisahkan concerns: actions, components, hooks, libs
- ✓ Gunakan naming conventions yang konsisten (camelCase untuk variables, PascalCase untuk components)

### 4. API Design
- ✓ Gunakan Next.js API Routes di `/api`
- ✓ Dokumentasikan setiap endpoint di `docs/API_REFERENCE.md`
- ✓ Return consistent response format: `{ success: boolean, data?: any, error?: string }`
- ✓ Gunakan proper HTTP status codes

### 5. Database Compatibility
- ✓ Pertahankan kompatibilitas dengan Firebase Realtime Database
- ✓ Jangan gunakan fitur Firestore yang tidak ada di Realtime DB
- ✓ Test setiap query dengan data real dari Firebase
- ❌ **JANGAN** migrasi ke Firestore tanpa dokumentasi lengkap

### 6. Component Organization
- ✓ Components di `/src/components` untuk reusable UI elements
- ✓ Container components untuk business logic
- ✓ Pisahkan modal components dalam subfolder
- ✓ Gunakan React hooks untuk state management

### 7. Actions & Server Functions
- ✓ Gunakan Server Actions (`'use server'`) untuk database operations
- ✓ Simpan di `/src/actions/admin/[entity]` dengan struktur yang jelas
- ✓ Validasi input di server, jangan percaya client
- ✓ Return proper error messages untuk debugging

### 8. Image Management
- ✓ Gunakan Cloudinary untuk semua image storage
- ✓ Simpan URL Cloudinary di Firebase (bukan binary image)
- ✓ Implement image optimization di `/src/components/uploder-image`
- ✓ Support multiple image formats (JPEG, PNG, WebP)

### 9. Form Validation
- ✓ Validasi di client dengan Zod/validation schema
- ✓ Validasi lagi di server sebelum database operation
- ✓ Berikan feedback yang jelas untuk setiap validation error
- ✓ Gunakan form state management yang konsisten

### 10. Documentation
- ✓ Dokumentasikan keputusan teknis di `/docs` folder
- ✓ Update `README.md` saat ada perubahan setup
- ✓ Tulis comments untuk logika yang kompleks
- ✓ Maintain `docs/NAVIGATION_SYSTEM.md` untuk keputusan navigasi

## Important Notes

- **Jangan commit** file dengan credential Firebase
- **Jangan skip** TypeScript type checking (`npm run type-check`)
- **Selalu test** dengan data real dari Firebase sebelum production
- **Document changes** yang significant untuk team
